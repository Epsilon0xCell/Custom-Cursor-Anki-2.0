What this is

I wrote this add-on because Anki gives you no way to change the mouse cursor, and I wanted my own pointer while I study. It is a small thing on purpose: two Python files, one config file, one manifest. You open the dialog from the Tools menu, pick an image, press Apply Cursor, and the cursor changes inside Anki. Reset Cursor puts the normal one back and clears the file field, so the dialog never shows a cursor that is no longer applied.

The config file is read once when Anki loads the add-on, so it works like a snapshot. If auto_apply is true and default_cursor names a file that exists, that cursor is applied at start-up. Edit the config and the change waits for the next start. That is not a bug I am hiding; it is how Anki imports add-on packages, and the code says so where the config is read.

An early version of this repo shipped with template leftovers in the manifest: the homepage pointed at a yourusername account and the author read "Your Name". Both now point at this repo and this account. The config was also loaded and then ignored in that version, with the shortcut hardcoded. It is read for real now.

Two findings from the bench

Finding 1: the Qt cursor stack

Qt override cursors are a stack. Each setOverrideCursor call pushes one, and each restoreOverrideCursor pops exactly one. My reset pops once. In Deep Wave 2 of the improvement campaign I found the fault that follows from that: apply a second cursor without popping the first, and one reset leaves the first custom cursor still active. set_cursor in __init__.py now restores the previous cursor before pushing a new one, so the stack depth stays at one no matter how often I apply. The code carries one setOverrideCursor call site and two restoreOverrideCursor call sites (one in set_cursor, one in reset_cursor), and a reset with nothing applied stays a no-op so it cannot pop a cursor some other add-on put there.

Finding 2: the invisible cursor refusal

A file can exist and still not be a loadable image. The browse filter offers .cur and .ani, and QPixmap cannot decode those on every platform, so existence is not proof. A null pixmap would have installed an invisible cursor and left the pointer gone for the session. set_cursor now checks pixmap.isNull() and refuses, the same way it refuses a missing or empty path by returning False without touching the cursor. From the dialog, the two cases get two different messages: "Please select a valid cursor file" for a missing path, and "That file could not be loaded as a cursor image" for a file Qt cannot load.

Install

1. Copy this folder into Anki's
   add-ons folder.
2. Restart Anki.
3. Open Tools, then Custom Cursor
   (default shortcut Ctrl+Shift+C).
4. Browse to an image file.
5. Press Apply Cursor.
   Press Reset Cursor to restore
   the normal cursor.

How this was checked, honestly

I verified this add-on with the campaign's own import-and-behavior harness: a stub aqt package built for the test, with a fake mw, aqt.qt, and aqt.utils, importing the add-on and driving set_cursor, the menu action, and the dialog. It was not verified by clicking through real Anki, because real Anki was not available on the test machine, and I will not claim a click test that never happened. Under the harness: the menu takes the configured shortcut, a missing path returns False and changes nothing, a .cur file is refused with no override pushed, a double apply keeps the stack at depth one, and one reset clears it.
