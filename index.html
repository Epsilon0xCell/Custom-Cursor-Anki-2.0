Custom-Cursor-Anki-2.0

The desktop workbench. An Anki add-on that applies a custom cursor inside Anki, laid out the way I work on it: tools on the bench, a test pad in the middle, and the code in the drawer.

Test padTry the pointer here first

Move your pointer across the mat below. Inside the mat, your pointer changes into the test cursor for this page, a 48 pixel arrow drawn in code as test-cursor.png in this site folder. That is the same trick the add-on pulls inside Anki, at page scale: an image file becomes the pointer over one surface, and the rest of the screen keeps its normal cursor. The three cards are flashcard shaped panels I drew for this pad, front and back, because a reviewer screen is the surface this add-on actually changes.

On a touch screen there is no pointer to change, so the pad answers a tap instead and names the card you tapped. That is the honest limit of a cursor demo on a phone, and I would rather say it than fake a hover.

The tray above is the whole format story in cursor_dialog.py: the browse filter is Images (*.png *.xpm *.jpg *.cur *.ani). The last two are offered and still refused at apply time on a platform where QPixmap cannot decode them. The refusal is in the drawer below.

The plain fact about this bench: this repo ships no cursor file at all. No .cur, no .ani, and no ready made cursor PNG. You bring your own image file, the add-on loads it, and that is the whole design. I did not invent a cursor set for this page and pretend it came with the add-on.

What this isTwo files, one job

I wrote this add-on because Anki gives me no way to change the mouse cursor, and I wanted my own pointer while I study. It stays small on purpose: __init__.py at 84 lines owns the menu and the cursor state, cursor_dialog.py at 84 lines is the settings dialog, and config.json and manifest.json sit beside them. Copy the folder into the Anki add-ons folder, restart Anki, and a Custom Cursor entry appears in the Tools menu.

Open the dialog, browse to an image file, and press Apply Cursor. Press Reset Cursor and the normal cursor comes back, and the file field clears with it, so the dialog never shows a cursor that is no longer applied. One dialog is kept and reused, so opening the menu twice does not stack windows.

The config is read once, when Anki imports the add-on. That makes config.json a snapshot: an edit waits for the next start. An earlier version of this add-on loaded that config and then ignored it, with the shortcut hardcoded. That is fixed, and the captures in the drawer are the proof, taken from the files as they stand now.

DrawerThe code, checked against the files

First fix: the config is read for real

The shortcut comes from config.json, with Ctrl+Shift+C only as the fallback for a missing or empty value. From __init__.py, the setup_menu method:

    def setup_menu(self):
        action = QAction("Custom Cursor", mw)
        # I use "or" for the fallback on purpose, not a default value in
        # the get call. A config that holds an empty shortcut string
        # counts as missing for me, and I still want a working shortcut.
        action.setShortcut(config.get("shortcut") or "Ctrl+Shift+C")
        action.triggered.connect(self.show_cursor_dialog)
        mw.form.menuTools.addAction(action)

Start-up apply is gated the same way in the manager: auto_apply and a non empty default_cursor must both be set before set_cursor is called at load. The config file itself, field for field, is this:

{
    "default_cursor": "",
    "auto_apply": false,
    "shortcut": "Ctrl+Shift+C"
}

Second fix: no cursor gets stranded on the stack

Qt override cursors are a stack. Each push needs one pop, and my reset pops once, so set_cursor restores the previous cursor before pushing the new one. The stack depth stays at one. From __init__.py, the end of set_cursor:

        if self.current_cursor is not None:
            mw.app.restoreOverrideCursor()

        cursor = QCursor(pixmap)
        mw.app.setOverrideCursor(cursor)
        self.current_cursor = cursor
        return True

Reset only pops when this add-on pushed, so a reset with nothing applied cannot pop a cursor some other add-on put on the stack.

Third fix: an unloadable file installs nothing

A file can exist and still not load. A null pixmap would have installed an invisible cursor, so set_cursor refuses it the same way it refuses a missing path. From __init__.py, the start of set_cursor:

    def set_cursor(self, cursor_path):
        if not cursor_path or not os.path.exists(cursor_path):
            return False

        pixmap = QPixmap(cursor_path)
        # I refuse a file that exists but is not a loadable image. The
        # browse filter offers .cur and .ani, and QPixmap cannot decode
        # those on every platform, so existence is not proof. A null
        # pixmap would install an invisible cursor, which is worse than
        # no change, so I treat it the same way as a missing file.
        if pixmap.isNull():
            return False

From the dialog, the two failures get two different messages, because only one of them is fixed by picking a file again. From cursor_dialog.py, in apply_cursor:

        if not cursor_path or not os.path.exists(cursor_path):
            showInfo("Please select a valid cursor file")
            return
        if not self._manager().set_cursor(cursor_path):
            showInfo("That file could not be loaded as a cursor image")

FittingInstall and the parts list

  1. Copy this folder into the Anki add-ons folder.
  2. Restart Anki.
  3. Open Tools, then Custom Cursor, or use the shortcut from config.json, default Ctrl+Shift+C.
  4. Browse to an image file. PNG, XPM, and JPG are the safe choices.
  5. Press Apply Cursor. Press Reset Cursor to restore the normal cursor.

StackPython, Qt through Anki and its aqt package. No other code ships in this repo.

Honest limits, from the README record: this add-on was checked with a stub aqt harness, not inside real Anki, because real Anki was not available in that pass. The menu entry, the shortcut from config, the refusal of a missing path, a valid apply, and a reset were checked that way. On this page, the only check I ran on the code itself is a compile check, since importing the add-on outside Anki needs aqt. I say that plainly rather than claim a run I did not do.
